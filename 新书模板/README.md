# 长篇小说新书模板

这套模板现在只解决两件事：

- 下一本小说可以直接开工
- 长连载时不靠反复喂全量上下文

先读 `小说SOP最终流程.md`。它是整套模板唯一保留的 SOP 流程入口。

## 开书顺序

1. 把你的原始大纲、脑洞或想法写进 `开书输入.md`
2. 按 `小说SOP最终流程.md` 的“开书初始化”部分执行
3. 检查并微调生成好的规划层文件：
   - `小说框架/00_作品定位.md`
   - `小说框架/01_世界观与主线.md`
   - `小说框架/02_人物关系表.md`
   - `小说框架/06_卷划分.md`
   - `小说框架/03_总目录.md`
   - `小说框架/04_节奏设计.md`
   - `小说框架/05_作品简介.md`
   - `小说框架/07_人物小传.md`
4. 确认已经生成：
   - 第一卷执行状态卡
   - 第 1 章任务卡
5. 再确认 `当前有效规则卡.md`

## 连载时默认维护三卡

1. `当前有效规则卡.md`
2. 当前卷执行状态卡
3. 当前章任务卡

日常写章另看：

- `SOP资料/skills/技能短卡.md` 中本章需要的 1-2 个摘要

不默认回读：

- `进度记录.md`
- `章节验收记录.md`
- `归档/`
- 全量 `小说框架/03_总目录.md`

这些文件只在卡住、误报、追旧线索或改卷节奏时回看。

## 常用命令

先生成本章最小上下文包：

```bash
python3 scripts/prepare_chapter_context.py \
  --volume-card 小说框架/第一卷执行状态卡.md \
  --task-card 小说框架/当前章任务卡.md \
  --output 小说框架/当前章上下文包.md
```

生成后，真正默认交给模型的是：

1. `当前章上下文包.md`
2. 当前待写 / 待修正文
3. 必要时的前 1 章正文；承接复杂时最多前 2 章

`当前章上下文包.md` 已经包含规则卡、状态卡、任务卡，不要再把三张源卡重复附送一遍。

草稿阶段先验收 `.txt` 或当前正文文件：

```bash
python3 scripts/run_chapter_acceptance.py --chapter 小说正文/源稿/001_章节名.txt
```

通过后再渲染 `.docx`，并做最终验收：

```bash
python3 scripts/run_chapter_pipeline.py --input 小说正文/源稿/001_章节名.txt
```

## 当前模板原则

- 新书不机械锁死固定总章数
- 卷划分、章节组块、阶段推进按当次大纲动态整理
- 原始大纲只在初始化阶段进入默认上下文，初始化完成后退回输入源
- 总目录属于规划层，不进入每章默认上下文
- 日常连载只维护规则卡、状态卡、任务卡和短日志
- 正文与框架正式交付统一使用真实 `.docx`

## 同步 SOP 资料

`SOP资料/` 已经内置在模板里，通常不用同步。

如果你在复制后的项目上级目录另维护了一套 SOP 源，并且它包含 `小说SOP最终流程.md`、`skills/`、`workflows/`，可以同步到模板：

```bash
python3 scripts/sync_sop_assets.py --source-root <SOP源目录>
```

不传 `--source-root` 时，脚本会先检查上级目录；如果当前是 aiReading 这种“根目录只保留入口和模板”的结构，会安全跳过。
