# 当前项目规则

> 适用于当前新书项目的写作、修订、补字、格式统一与交付工作。
> 若后续新增规则与本文件冲突，以你最新确认的规则为准。

## 一、章节与结构规则

1. 章节规划不固定总章数。
2. 卷划分、章节组块与阶段推进，按当次大纲分析自由总结。
3. 不得脱离当前大纲、主线、人物关系和时间线乱改结构。
4. 若当次任务只处理既有章节，默认不擅自合并章节、不擅自拆章。
5. 章节标题格式统一为：`第X章 XXXXX`。
6. 所有修改必须在原有剧情基础上补强，而不是另起一套内容。

## 二、内容修改规则

1. 修改方向包括：
   - 文案调整
   - 内容补充
   - 流水账修正
   - 场景补强
   - 动作补强
   - 对话补强
   - 情绪落地
   - 主线 / 支线 / 关系线推进
2. 补写必须是有效内容，禁止：
   - 模板化凑字
   - 重复段落
   - 重复表意
   - 同义反复硬拉字数
   - 空泛抒情
   - 无效水字数
3. 正文必须像小说，不像提纲，不像流水账，不像剧情汇报。
4. 段落要求：
   - 以短段为主
   - 单段尽量控制在 2-3 行的阅读体感
   - 转折、动作、对话、情绪变化及时拆段

## 三、字数规则

1. 每章目标字数：3200-3800 字。
2. 每章最低字数：不低于 3200 字。
3. 字数统计默认只算正文，不算标题。
4. 低于 3200 字的章节必须补；已达标章节如无额外要求可不动。
5. 若补写后超过 3800 字，需要回调到合理区间内。

## 四、格式规则

1. 正式交付统一使用真实 `.docx`。
2. 不允许使用 HTML 伪装 `.doc`。
3. 不允许用 markdown 代替正式正文文件。
4. 页面设置：
   - 上边距：2.54 厘米
   - 下边距：2.54 厘米
   - 左边距：2.8 厘米
   - 右边距：2.6 厘米
5. 标题格式：
   - 黑体三号
   - 居中
   - 单独成行
6. 正文格式：
   - 宋体小四
   - 固定 29 磅行距
   - 首行缩进 2 字符
   - 段前 0
   - 段后 0
7. 不允许：
   - 用连续空行撑版
   - 出现乱码
   - 出现异常空格
   - 出现广告
   - 出现外链

## 五、内容边界规则

- 不涉政
- 不涉黄
- 不涉暴
- 不写过于惊悚的灵异鬼怪与封建迷信
- 不抹黑现实人物与现实职业

## 六、执行流程规则

1. 每一批任务开始前，先更新 `进度记录.md`。
2. 每修改完一个文件，立刻更新 `进度记录.md`。
3. 不允许只有口头汇报，没有文件内进度留痕。
4. 每一批任务结束后，汇总说明：
   - 本批修改了哪些章节
   - 哪些章节未修改
   - 为什么未修改
   - 下一步准备处理哪些章节
5. 每章初稿或修订稿完成后，先运行 `scripts/run_chapter_acceptance.py --chapter ...`。
6. 每次验收结果，写入 `章节验收记录.md`。
7. 若验收结论为“不通过”，默认不进入下一章。
8. 自动验收默认至少覆盖：标题字数、重复回退、显式逻辑冲突、连续性强信号、情绪承接、关键决策代价、主支线漂移。
9. 若根目录 SOP 升级过验收规则，开新书前先运行一次 `scripts/sync_sop_assets.py`，再开始写。
