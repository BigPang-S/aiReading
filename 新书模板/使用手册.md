# 新书模板使用手册

这份手册面向两个目标：

- 把 `新书模板/` 当成一个可以直接复制开工的长篇小说项目
- 把根目录现有的 SOP、skills、workflows 一起打包带走，避免开新书时资料分散

## 一、项目结构

`新书模板/` 现在分成四层：

1. 项目执行层
   - `项目规则.md`
   - `进度记录.md`
   - `章节验收记录.md`
2. 规划层
   - `小说框架/`
3. 自动化层
   - `scripts/run_chapter_acceptance.py`
   - `scripts/sync_sop_assets.py`
4. SOP 资料层
   - `SOP资料/说明文档/`
   - `SOP资料/skills/`
   - `SOP资料/workflows/`

## 二、第一次开书怎么用

推荐顺序：

1. 先看 `README.md`
2. 再看 `项目规则.md`
3. 填 `小说框架/00_作品定位.md`
4. 填 `小说框架/01_世界观与主线.md`
5. 填 `小说框架/02_人物关系表.md`
6. 填 `小说框架/06_卷划分.md`
7. 填 `小说框架/03_总目录.md`
8. 再补 `04_节奏设计.md`、`05_作品简介.md`、`07_人物小传.md`

如果你中途不知道该调用哪个 skill，先看：

- `SOP资料/说明文档/总览说明.md`
- `SOP资料/workflows/技能索引清单.md`
- `SOP资料/skills/小说写作总控skill/SKILL.md`

## 三、写一章时怎么用

默认流程：

1. 先看当前章在 `小说框架/03_总目录.md` 里负责什么
2. 按 `SOP资料/workflows/章节创作工作流模板.md` 起草
3. 写作时按问题调用对应 skill
4. 写完后运行章节验收
5. 通过后再进入下一章

推荐入口：

- 不知道先修哪儿：`SOP资料/skills/小说写作总控skill/SKILL.md`
- 从零写一章：`SOP资料/workflows/章节创作工作流模板.md`
- 修一章：`SOP资料/workflows/章节修订工作流模板.md`

## 四、章节验收怎么用

在项目根目录执行：

```bash
python3 scripts/run_chapter_acceptance.py --chapter 小说正文/001_章节名.docx
```

脚本会自动：

- 读取 `项目规则.md`
- 读取 `小说框架/03_总目录.*`
- 对照 `小说正文/` 里的前文章节
- 调用章节验收脚本
- 把结果追加到 `章节验收记录.md`

当前自动验收默认会覆盖四类问题：

- 硬规则：标题、字数、重复、乱码、外链、异常 HTML
- 显式逻辑：数量、时间、称谓、身份、场景、物件状态等硬冲突
- 连续性：伤势、库存、在场性、权限、伏笔、承诺、阶段目标、资源闭环等强信号
- 稳定性：情绪承接缺口、关键决策缺代价、支线抢主线、章尾钩子失效等高风险问题

验收结论分三档：

- `通过`：可以继续
- `警告`：可继续，但要记住风险
- `不通过`：先修，再继续

## 五、每天连载时建议保持的节奏

最稳的执行节奏：

1. 开始写之前，先看本章对应的大纲条目
2. 写完后先自检一次
3. 跑自动验收
4. 记录到 `进度记录.md` 和 `章节验收记录.md`
5. 再决定是否进入下一章

这一步的目的是防止：

- 章节虽然成稿，但没真的推进
- 补字后重复变多
- 大纲推进错位
- 人物关系和时间线写乱

## 六、SOP 资料怎么维护

模板里的 `SOP资料/` 是从仓库根目录同步过来的自包含资料包。

如果根目录的说明文档、skills、workflows 更新了，在仓库根目录执行：

```bash
python3 新书模板/scripts/sync_sop_assets.py
```

运行后会把下面这些内容重新同步进模板：

- `总览说明.md`
- `给下一个工具的接管说明.md`
- `skills/`
- `workflows/`

其中也包括最新的章节验收规则和 `chapter_guard.py` 脚本实现。

## 七、哪些文件是“项目真文件”

真正会随着一本书长期维护的，主要是这些：

- `项目规则.md`
- `进度记录.md`
- `章节验收记录.md`
- `小说框架/`
- `小说正文/`（后续你自己新增）

`SOP资料/` 更像模板内置知识库，平时查阅和调用，不直接承载小说正文。
如果你把整套模板单独复制到别处，章节验收脚本也能直接回退使用这里的 `SOP资料/skills/novel-chapter-acceptance/`。

## 八、git 使用建议

当前仓库还没有远端。

你现在可以先做两件事：

1. 本地提交这套模板整理结果
2. 后续补上远端地址，再 push

最小流程：

```bash
git add .
git commit -m "整理新书模板与SOP资料包"
git remote add origin <你的仓库地址>
git push -u origin main
```

## 九、当前模板的定位

这不是单纯的“几个空白 md 模板”，而是一套可直接执行的项目包：

- 有框架模板
- 有项目规则
- 有进度记录
- 有章节验收
- 有完整 SOP 资料
- 有自动同步和自动验收脚本

所以后面你要开第二本、第三本，直接复制 `新书模板/` 就能继续用。
