# 新书模板使用手册

这份手册面向两个目标：

- 把 `新书模板/` 当成一个可以直接复制开工的长篇小说项目
- 把连载时真正需要反复执行的 SOP 压缩成低 token 工作流

## 一、项目结构

`新书模板/` 现在分成四层：

1. 项目执行层
   - `开书输入.md`
   - `项目规则.md`
   - `进度记录.md`
   - `章节验收记录.md`
2. 规划层
   - `小说框架/`
3. 自动化层
   - `scripts/run_chapter_acceptance.py`
   - `scripts/sync_sop_assets.py`
4. SOP 资料层
   - `SOP资料/说明文档/`
   - `SOP资料/skills/`
   - `SOP资料/workflows/`

另外有几份直接开工时最重要的入口文件：

- `开书输入.md`
- `下一本小说直用工作流.md`
- `当前有效规则卡.md`
- `SOP资料/workflows/开书初始化工作流.md`
- `小说框架/09_当前卷执行状态卡_模板.md`
- `小说框架/10_当前章任务卡_模板.md`
- `SOP资料/说明文档/Codex开书初始化提示模板.md`
- `SOP资料/说明文档/Claude-Mem与RTK接入规则.md`

## 二、第一次开书怎么用

推荐顺序：

1. 先看 `README.md`
2. 再看 `下一本小说直用工作流.md`
3. 把现有大纲、脑洞、人物设定或片段想法写进 `开书输入.md`
4. 再看 `项目规则.md`
5. 再看 `SOP资料/workflows/开书初始化工作流.md`
6. 如果你在 Codex 里直接开工，直接套 `SOP资料/说明文档/Codex开书初始化提示模板.md`
7. 让 Codex 先做一次开书初始化，生成：
   - `小说框架/00_作品定位.md`
   - `小说框架/01_世界观与主线.md`
   - `小说框架/02_人物关系表.md`
   - `小说框架/06_卷划分.md`
   - `小说框架/03_总目录.md`
   - `小说框架/04_节奏设计.md`
   - `小说框架/05_作品简介.md`
   - `小说框架/07_人物小传.md`
   - 第一卷执行状态卡
   - 第 1 章任务卡
8. 检查初始化结果，只修你真正想改的设定，不再继续反复喂原始大纲

如果你中途不知道该调用哪个 skill，先看：

- `SOP资料/说明文档/总览说明.md`
- `SOP资料/workflows/技能索引清单.md`
- `SOP资料/skills/小说写作总控skill/SKILL.md`

## 三、写一章时怎么用

默认流程：

1. 先看 `当前有效规则卡.md`
2. 再看带来源章号的当前卷状态卡
3. 再看当前章任务卡
4. 承接复杂时，最多回读前 2 章正文；不默认回读全量总目录
5. 先运行一次最小上下文包生成脚本
6. 按 `SOP资料/workflows/低Token连载工作流模板.md` 执行；需要展开时再回到创作或修订 workflow
7. 写作时按问题调用对应 skill
8. 写完后先顺手扫一遍“不是……却是…… / 原来…… / 说到底……”这类总结句，能拆就拆
9. 如果明显有“太会总结 / 太会解释 / 太会说 / 太会点题”的问题，先走 `SOP资料/workflows/去AI味修订工作流模板.md`
10. 逐句通读一轮，再运行章节验收
11. 通过后更新状态卡、任务卡和短记录，再进入下一章

推荐入口：

- 不知道先修哪儿：`SOP资料/skills/小说写作总控skill/SKILL.md`
- 从零写一章：`SOP资料/workflows/章节创作工作流模板.md`
- 修一章：`SOP资料/workflows/章节修订工作流模板.md`
- 专项去 AI 味：`SOP资料/workflows/去AI味修订工作流模板.md`

## 四、章节验收怎么用

在项目根目录执行：

```bash
python3 scripts/run_chapter_acceptance.py --chapter 小说正文/001_章节名.docx
```

脚本会自动：

- 读取 `项目规则.md`
- 读取 `小说框架/03_总目录.*`
- 对照 `小说正文/` 里的前文章节
- 调用章节验收脚本
- 以短记录模式追加到 `章节验收记录.md`

验收结论分三档：

- `通过`：可以继续
- `警告`：可继续，但要记住风险
- `不通过`：先修，再继续

如果当前手里还是源稿 `.txt`，可以直接一步跑完：

```bash
python3 scripts/run_chapter_pipeline.py --input 小说正文/源稿/001_章节名.txt
```

默认行为：

- 自动渲染 `.docx`
- 自动运行章节验收
- 自动追加 `章节验收记录.md`
- 自动追加一条 `进度记录.md` 短记录

## 五、低 Token 连载怎么用

这套模板现在默认不是“三层文件法”，而是“四卡双日志法”：

1. `当前有效规则卡.md`
2. 当前卷执行状态卡
3. 当前章任务卡
4. 当前章上下文包
5. `进度记录.md`
6. `章节验收记录.md`

其中真正喂给模型的，默认只有：

- `当前章上下文包.md`
- 当前待写正文 / 待修正文

`开书输入.md` 只在两种时候默认回读：

- 第一次开书初始化
- 整体重做规划层或大改卷方向

进入正式连载后，不再把 `开书输入.md` 当成日常上下文。

### 当前章上下文包怎么生成

```bash
python3 scripts/prepare_chapter_context.py \
  --volume-card 小说框架/第一卷执行状态卡.md \
  --task-card 小说框架/当前章任务卡.md \
  --output 小说框架/当前章上下文包.md
```

这个脚本会做三件事：

- 把规则卡、状态卡、任务卡拼成一份最小上下文包
- 检查状态卡和任务卡有没有写得过长
- 在超出默认预算时直接报错，逼你先压缩卡片

### 为什么这样能省 token

因为以后总目录只在“建任务卡”时读一次，不再每章陪跑。
进度记录和验收记录只做日志，不进入日常上下文。
真正滚动更新的只有：

- 当前卷状态
- 当前章任务
- 最近 1 到 2 章承接

## 六、Claude-Mem 与 RTK 怎么接

先看：

- `SOP资料/说明文档/Claude-Mem与RTK接入规则.md`

模板里的默认原则是：

- Claude-Mem 只做跨会话元记忆，不做剧情 canon
- RTK 只压终端输出，不压正文和状态卡

推荐命令：

```bash
rtk tree -L 2 .
rtk find -name '*状态卡*'
rtk grep '第43章' 小说框架
rtk git status
rtk git diff README.md 使用手册.md
```

接好外部工具后，可以跑一次审计：

```bash
python3 scripts/audit_assistant_tooling.py
```

这个脚本会检查：

- Claude-Mem 是否排除了泛项目名
- Claude-Mem 是否处于低 token 配置
- RTK telemetry 是否关闭

## 七、每天连载时建议保持的节奏

最稳的执行节奏：

1. 开始写之前，先更新当前章任务卡
2. 生成 `当前章上下文包.md`
3. 只看规则卡、状态卡、任务卡和最近承接
4. 写完后先自检一次
5. 如果自检时发现太会总结、太会解释、太会说或太知道主题，先走一次去 AI 味 workflow
6. 逐句通读一次
7. 跑自动验收
8. 只把必要结果记到状态卡、任务卡、`进度记录.md` 和 `章节验收记录.md`
9. 再决定是否进入下一章

这一步的目的是防止：

- 章节虽然成稿，但没真的推进
- 补字后重复变多
- 大纲推进错位
- 人物关系和时间线写乱
- 旁白一段段替正文总结主题，句子太工整，读着像文案
- 状态卡和任务卡越来越长，最后比正文还费 token

## 八、SOP 资料怎么维护

模板里的 `SOP资料/` 是从仓库根目录同步过来的自包含资料包。

如果根目录的说明文档、skills、workflows 更新了，在仓库根目录执行：

```bash
python3 新书模板/scripts/sync_sop_assets.py
```

运行后会把下面这些内容重新同步进模板：

- `总览说明.md`
- `给下一个工具的接管说明.md`
- `skills/`
- `workflows/`

## 九、哪些文件是“项目真文件”

真正会随着一本书长期维护的，主要是这些：

- `当前有效规则卡.md`
- `项目规则.md`
- `进度记录.md`
- `章节验收记录.md`
- 当前卷执行状态卡
- 当前章任务卡
- `小说框架/`
- `小说正文/`（后续你自己新增）
- `归档/`

`SOP资料/` 更像模板内置知识库，平时查阅和调用，不直接承载小说正文。

## 十、git 使用建议

当前仓库还没有远端。

你现在可以先做两件事：

1. 本地提交这套模板整理结果
2. 后续补上远端地址，再 push

最小流程：

```bash
git add .
git commit -m "整理新书模板与SOP资料包"
git remote add origin <你的仓库地址>
git push -u origin main
```

## 十一、当前模板的定位

这不是单纯的“几个空白 md 模板”，而是一套可直接执行的项目包：

- 有框架模板
- 有项目规则
- 有下一本书的直用工作流
- 有状态卡和任务卡模板
- 有进度记录
- 有章节验收
- 有完整 SOP 资料
- 有自动同步、自动验收、最小上下文包和外部工具审计脚本

所以后面你要开第二本、第三本，直接复制 `新书模板/` 就能继续用。
