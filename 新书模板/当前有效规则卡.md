# 当前有效规则卡

这张卡只保留日常连载必须反复执行的硬规则。生成 `当前章上下文包.md` 时默认读取它，不先翻全量日志。

## 默认读取顺序

维护卡片或生成上下文包时：

1. `当前有效规则卡.md`
2. 当前卷执行状态卡
3. 当前章任务卡
4. 前 1 章正文；承接复杂时最多前 2 章正文

只有遇到以下情况，才回看 `归档/`、`进度记录.md`、`章节验收记录.md`：
- 当前章和前文状态对不上
- 自动验收出现误报，需要人工复核
- 章与章之间的承接点不清
- 需要追查某个旧决定、旧物件、旧关系

只有遇到以下情况，才回看 `小说框架/03_总目录.md`：

- 新建下一章任务卡
- 需要改卷节奏
- 验收显示本章可能没有按大纲推进

## 硬规则

- 章节标题统一为：`第X章 XXXXX`
- 每章目标 `3200-3800` 字，最低不低于 `3200` 字
- 正式交付统一使用真实 `.docx`
- Word 版式：标题黑体三号居中；正文宋体小四；首行缩进 2 字符；固定 29 磅行距；页边距上 2.54 / 下 2.54 / 左 2.8 / 右 2.6 厘米
- 不脱离当前大纲、时间线、人物关系乱改
- 默认不擅自拆章、并章、重排章节顺序
- 内容边界：不涉政、不涉黄、不涉暴，不写过度惊悚灵异或封建迷信，不抹黑现实人物与职业

## 内容规则

- 补写只能补有效推进，不能靠重复、复述、空抒情凑字数
- 先修结构，再修场景人物，最后修语言
- 去 AI 味默认顺序：先删解释，再看节奏，再补细节，最后修句子
- 每章必须落到明确结果，并留下一扇往下走的门
- 少写“先否后明”和替正文下结论的句子；如果提纲里已经这样写，先改成动作句再落正文
- 一旦出现连续两句解释、段尾点题、作者替人物定性、冲突立刻被理解、删掉心理句整段塌掉，按结构问题回场景层重写，不只润色

## 上下文预算规则

- 当前卷执行状态卡的 `主线进度 / 资源 / 人物位置 / 关系 / 外部压力` 每栏最多 `4` 条
- 当前章任务卡默认只保留：本章要办成的事、必须承接、不能写、完成判定
- `进度记录.md` 和 `章节验收记录.md` 只做日志，不进入每章默认上下文
- 单次交给模型的最小上下文包默认不超过 `4000` 字；超了先压状态卡和任务卡，不先加 token
- `当前章上下文包.md` 已经包含规则卡、状态卡、任务卡；给模型时不要再把三张源卡重复附上
- 总目录属于规划层，不属于每章默认上下文

## 低 Token 执行法

- 活跃文件只保留当前卷状态、当前章任务、最近批次、未清风险
- 历史详单转入 `归档/`
- 每章开工前先生成一份 `当前章上下文包.md`
- 默认只把 `当前章上下文包.md`、当前待写正文和必要前章交给模型
- 日常只读 `SOP资料/skills/技能短卡.md` 中本章需要的摘要；完整 skill / workflow 只在专项任务中打开
- 不接入外部记忆或终端压缩工具；故事事实、流程判断和执行口都以项目文件为准
- 自动验收默认写短记录
- 人工补充只写三类东西：误报复核、真实风险、卷间交接点
- 状态卡每条事实必须带 `[源：第X章]`；推断必须单列为 `[推断：基于第X章]`
