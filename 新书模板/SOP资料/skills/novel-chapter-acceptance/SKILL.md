# 章节验收与连续性校验

这个 skill 是辅助验收层，不替代现有 6 个基础写作 skill。

它的职责不是直接写正文，而是判断：
- 这一章能不能交付
- 这一章是否符合当前项目规则
- 这一章是否真的把故事往前推了一步
- 这一章是否开始出现回退、复读、串线和整体混乱

## 核心目标

每章完成后，给出一份可执行的验收结论：
- `通过`：可继续进入下一章
- `警告`：可以进入下一章，但必须记住风险点
- `不通过`：必须先修，再继续连载

## 验收分层

### 第一层：硬规则校验

必须检查：
- 标题格式是否为 `第X章 XXXXX`
- 正文字数是否符合当前规则
- 是否存在重复段落、重复表意、同义反复硬拉长度
- 是否存在乱码、广告、外链、异常 HTML 痕迹
- 是否存在明显超长段落

### 第二层：本章成立性校验

必须回答：
- 这章有没有明确任务
- 这章有没有场景承载
- 这章有没有结果，而不是只搬信息
- 这章有没有人物关系或主线状态变化
- 章尾有没有继续阅读牵引力

### 第三层：大纲推进校验

必须判断：
- 这章是否对应当前目录 / 大纲里应做的那一步
- 是否真的把主线、支线、关系线向前推了
- 是否偷跑了后面才该发生的内容
- 是否把已经完成的节点又重新写一遍

### 第四层：连载连续性校验

必须检查：
- 时间线有没有倒退或跳乱
- 人物关系温度是否连续
- 人物立场、口气、动作习惯是否突然变形
- 经营 / 生计 / 任务状态是否与前文一致
- 是否把前 1 到 3 章已经说明过的信息大量复述
- 是否因为补字导致“看起来热闹，实则不前进”

## 默认执行流程

### 1. 先读当前有效规则

优先读取：
- `当前有效规则卡.md`
- 当前卷状态卡
- `项目规则.md`
- `小说框架/03_总目录.*`
- `小说框架/06_卷划分.*`
- `进度记录.md`

如果当前项目没有这些文件，至少要拿到：
- 当前章节
- 当前阶段大纲
- 前 1 到 3 章正文

低 token 模式下，默认先读 `当前有效规则卡.md` 和带来源章号的当前卷状态卡；只有承接不清或脚本结果异常时，才回看全量 `进度记录.md`。

### 2. 先跑脚本做硬规则体检

如果当前章节已经落地为文件，优先运行：

```bash
python3 skills/novel-chapter-acceptance/scripts/chapter_guard.py \
  --chapter 路径/到/当前章节.docx \
  --rules 路径/到/项目规则.md \
  --outline 路径/到/小说框架/03_总目录.md \
  --previous-dir 路径/到/小说正文
```

脚本负责给出：
- 标题格式
- 正文字数
- 章节编号连续性
- 当前章内重复段落
- 与前文章节的高相似重复
- 上一章尾段与本章开头的复述重叠
- 大纲中是否能找到当前章节条目

如果没有文件，跳过脚本，直接做人工语义验收。

### 3. 再做语义验收

拿到脚本结果后，再人工补完下面四个判断：

1. **这章推进了什么**
2. **这章对应大纲的哪一步**
3. **这章是否把上一阶段已经成立的结果写回去了**
4. **这章是否因为补字让重复信息变多，但有效推进没变多**
5. **这章有没有一串太像作者代言的总结句，比如“不是……却是…… / 原来…… / 说到底……”，如果有，能不能先拆回具体人事**

### 4. 最后给出交付结论

输出时固定分成三档：
- `阻塞问题`
- `风险警告`
- `通过结论`

如果存在阻塞问题，不要把这章当成已验收通过。

### 4.5 记录要用短模式

默认把自动验收写成短记录，只保留：
- 时间
- 文件
- 结论
- 字数
- 大纲匹配
- 阻塞问题
- 风险警告

不要默认把执行命令、通过项摘要、长段人工总结每章都重复抄进记录。

人工补充只在三种情况下追加：
- 自动验收出现明显误报，需要人工压实
- 本章虽然能过，但有真实连续性风险必须给下一章留口
- 正好处在卷尾 / 卷首交接，需要把承接点写清

如果当前卷状态卡中的事实没有来源章号，默认视为不可靠摘要，验收时优先回读正文确认。

## 大纲推进检查问题单

验收时必须逐条过：

1. 当前章节在总目录里本来应该完成什么？
2. 本章结尾时，人物处境是否比开头更靠近下一节点？
3. 本章是否只是把上一章的结论换个场景再说一遍？
4. 本章新增的信息、关系变化、经营变化、决定变化分别是什么？
5. 如果删掉这章，后文会不会少掉一个必要台阶？
6. 如果删不掉，说明这章有推进；如果删掉也不影响，说明这章大概率发空。
7. 这章有没有老想替自己总结主题？如果把那些总结句先删掉，场景还立不立得住？

## 连续性检查问题单

重点盯下面几类容易写乱的点：

- 时间：今天、次日、隔天、季节、阶段是否对得上
- 地点：人物上一章在哪里，这章为什么能到这里
- 物件：钱、货、伤、药、书信、工具、铺子、田地等状态是否连续
- 关系：上一章刚冷下去，这章不能无因变热；上一章刚立边界，这章不能无因退回去
- 情绪：人物不能每章都重新震惊、重新难过、重新下决心
- 经营：已解决的问题不能反复当“第一次难题”重写

## 常见不通过情形

### 1. 章节像在原地踏步

表现：
- 写了很多动作和对话，但结局状态没变
- 章尾没有新门口，只是把本章内容再总结一遍

修法：
- 补一个明确结果
- 补一个下一步成本、风险或新机会

### 2. 章节把前文又写一遍

表现：
- 上一章刚讲过的处境，这章开头又大段复述
- 人物又重新想了一遍读者已经知道的事

修法：
- 删复述
- 只保留最短承接
- 把篇幅换成新动作、新判断、新后果

### 3. 章节推进和大纲错位

表现：
- 该发生在后面的节点提前发生
- 当前章标题和实际内容不一致
- 大纲写的是“立规矩”，正文大半却在重复“为什么要立规矩”

修法：
- 先对齐本章功能
- 再删掉跑偏内容

### 4. 补字后整体更乱

表现：
- 字数上去了，但重复句和回顾句显著变多
- 新增内容没有引起关系、主线或结果变化

修法：
- 先删重复
- 再补有效推进
- 验收标准看“状态变化”，不看“新增字数”

## 输出要求

验收结论必须包含：
- 当前章节结论：通过 / 警告 / 不通过
- 当前章节匹配的大纲条目
- 这章推进了什么
- 发现了哪些回退 / 重复 / 串线风险
- 如果不通过，必须指出先修哪几处

## 备注

这个 skill 最适合在以下时机调用：
- 每章初稿写完后
- 每章修订完成后
- 批量补字完成后
- 准备进入下一章前

如果任务是长期连载，默认把这个 skill 作为每章结束后的固定验收步骤。
