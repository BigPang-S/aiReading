# 低Token连载工作流模板

这份流程不是替代原有创作与修订 workflow，而是给长篇连载降上下文成本用的。

核心目标只有一个：

- 把规划层、连载层、日志层拆开
- 不让同一批信息在每一章里反复读取、反复改写、反复留痕

现在默认使用的是：

- 四卡双日志法

四卡：

1. `当前有效规则卡.md`
2. 当前卷执行状态卡
3. 当前章任务卡
4. 当前章上下文包

双日志：

1. `进度记录.md`
2. `章节验收记录.md`

## 零、开书输入只在初始化阶段使用

`开书输入.md` 的职责是承接用户原始大纲、脑洞和设定碎片。

它只在两种时候默认回读：

- 第一次开书初始化
- 整体重做规划层或大改卷方向

规划层和活跃卡生成后，日常连载不再默认回读 `开书输入.md`。
否则你只是把“原始输入”换了个文件名，token 还是会继续失控。

## 一、三层信息法

连载时，把信息固定分成三层：

### 第一层：稳定规则

长期不怎么变的东西，放在：

- `当前有效规则卡.md`
- `项目规则.md`

日常默认只读 `当前有效规则卡.md`。
只有要改规则时，才回看 `项目规则.md`。

### 第二层：当前卷状态

会随着当前卷推进滚动更新，但不该写成流水账的东西，放在：

- 当前卷状态卡
- 当前章任务卡

状态卡只写：

- 这卷的目标
- 已完成到哪里
- 关键人物现在站在哪里
- 当前资源、关系、外部压力
- 下一章必须承接什么
- 什么内容现在不能越界写
- 每条事实对应哪几章

状态卡默认使用：

- `小说框架/09_当前卷执行状态卡_模板.md`

每条事实必须带来源：

- 事实：`[源：第27-28章]`
- 推断：`[推断：基于第27-28章]`

任务卡只写：

- 本章只办成哪几件事
- 本章必须承接什么
- 本章不能提前写什么
- 本章完成判定是什么

任务卡默认使用：

- `小说框架/10_当前章任务卡_模板.md`

### 第三层：执行记录

真正的过程留痕，分两种：

- `进度记录.md`
- `章节验收记录.md`

这两份文件只保留：

- 当前卷
- 最近批次
- 未清风险

更早、更细的历史统一转 `归档/`。

## 二、每次开工默认读取顺序

1. `当前有效规则卡.md`
2. 当前卷状态卡
3. 当前章任务卡
4. 前 1 章正文；承接复杂时最多前 2 章

开工前默认先生成一份上下文包：

```bash
python3 scripts/prepare_chapter_context.py \
  --volume-card 小说框架/第一卷执行状态卡.md \
  --task-card 小说框架/当前章任务卡.md \
  --output 小说框架/当前章上下文包.md
```

只有出现下面几种情况，才翻全量记录：

- 当前章和前文物件、关系、时间对不上
- 自动验收结果看起来像误报
- 需要追一条旧线索究竟在哪章落下
- 当前卷状态卡明显过期

只有出现下面几种情况，才回读总目录：

- 当前章任务卡需要重建
- 要改卷节奏
- 当前章验收显示推进错位

## 三、单章执行最小流程

1. 先用总目录或单章提纲，提炼出一张当前章任务卡
2. 用规则卡和状态卡确认本章任务与禁越界内容
3. 生成 `当前章上下文包.md`
4. 起草或修正文
5. 逐句通读一次
6. 渲染 `.docx`
7. 运行章节验收
8. 更新四处短记录：

- 当前卷状态卡
- 当前章任务卡
- `进度记录.md`
- `章节验收记录.md`

更新状态卡时，只改发生变化的条目，并补上新的来源章号。
更新任务卡时，只保留下一章还真的需要继续使用的内容。

## 四、短记录规则

### 进度记录

一条单文件记录只写：

- 时间
- 文件
- 动作
- 改前 / 改后字数
- 状态

不要在进度记录里重复长段“本章推进了什么”。
卷内推进摘要写进当前卷状态卡，不重复写三遍。
状态卡里的摘要必须带来源章号，不能写无来源判断。

### 章节验收记录

自动验收默认短记录，只保留：

- 时间
- 文件
- 结论
- 字数
- 大纲匹配
- 阻塞问题
- 风险警告

人工补充只在三种情况下追加：

- 自动验收出现明显误报，需要复核
- 本章虽然通过，但有真实连续性风险必须记住
- 这一章正好是卷间交接章，需要给下一章留下承接点

## 五、硬性预算

默认预算不是建议，是硬约束：

- 当前卷状态卡每个栏目最多 `4` 条
- 当前章任务卡每个栏目最多 `4` 条
- `当前章上下文包.md` 默认不超过 `4000` 字
- 如果超预算，不先补 token，先压缩状态卡和任务卡

压缩原则：

- 合并相邻几章已经稳定的事实
- 删除已失效结果
- 不把“发生过什么”全写一遍，只写“现在有效的是什么”
- 总目录只承担规划，不承担每章陪跑

## 六、Claude-Mem 与 RTK 接法

### Claude-Mem

Claude-Mem 只承担“元记忆层”：

- 哪套流程更稳
- 哪些修订问题反复出现
- 哪些命令和排障方式有效
- 哪些偏好在跨会话后还稳定成立

Claude-Mem 不承担“故事事实层”：

- 不替代状态卡
- 不替代任务卡
- 不替代验收记录
- 不替代人物关系、资源和时间线

### RTK

RTK 只接到 shell 输出层：

- `rtk tree`
- `rtk find`
- `rtk grep`
- `rtk git ...`
- `rtk log`

不要拿 RTK 压：

- 正文源稿
- 卷状态卡
- 章任务卡
- 验收全文

因为这几类文件的价值就在细节，压缩后容易误判。

## 七、卷结束时怎么收口

一卷完成后，立刻做四件事：

1. 把当前 `进度记录.md` 全量复制到 `归档/`
2. 把当前 `章节验收记录.md` 全量复制到 `归档/`
3. 重写活跃版 `进度记录.md` 和 `章节验收记录.md`，只留归档索引和当前卷摘要
4. 新建下一卷状态卡

不要把上一卷状态卡原样续写到下一卷。
下一卷重开时，只保留仍然有效的事实。

## 八、什么时候不能只靠短流程

下面这些情况，不要硬省 token：

- 发现人物关系可能已经写乱
- 某条物资线、时间线连续多章出问题
- 要改的是整卷节奏，而不是单章
- 要回修前文多章，不是接着往下写

遇到这些情况，可以临时回到完整 workflow，但做完要重新压缩回状态卡。
