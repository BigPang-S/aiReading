# 给下一个工具的接管说明

这套资料位于：

`/Users/songzijian/ai小说/base`

它不是零散笔记，而是一套已经分层整理过的**中文小说 / 网文写作 SOP 基础系统**。

请把它理解为三层：

1. **skills/**：能力型 skill
2. **workflows/**：流程型模板
3. **总览说明.md**：入口说明

---

## 一、这套资料是怎么来的

这套资料不是凭空整理出来的，而是从一次连续的小说写作沟通里，逐步抽象出来的。

最开始，我们围绕一部中文种田文小说，持续讨论了：
- 正文怎么避免流水账
- 场景怎么承载气氛与压力
- 情绪怎么通过动作落地
- 人物动作怎么区分
- 人物台词怎么区分
- 同一角色面对不同人时，对话如何变化

之后，这些经验被从“某一本小说的局部经验”抽象成了：
- 可复用的基础 skill
- 可复用的工作流模板
- 可复用的总控调度逻辑

所以这套资料本质上是一套**从实战对话中长出来的 SOP**，不是空泛方法论。

---

## 二、使用这套资料时的总原则

### 1. 不要脱离原始 SOP 骨架
后续如果继续升级 skill，允许：
- 增补例子
- 增补反例
- 增补更细的调用流程
- 增补适用 / 不适用场景

但不要破坏当前 6 类基础问题划分：
1. 正文语言风格
2. 场景描写
3. 情绪动作表达
4. 人物专属动作签名
5. 人物专属台词签名
6. 人物关系对话

以及 1 个总控 skill：
7. 小说写作总控skill

新增的验收类 skill 允许补充，但不要把它并进原来的 6 类基础写作问题里。
当前已补充：
- 章节验收与连续性校验：用于章节完成后的硬规则验收、推进度验收与连续性校验

### 2. skill 的升级方向应当是“更可执行”，不是“更空泛”

### 2.5 字数规则不能凌驾于正文质量
- 不能为了凑字数而凑字数。
- 不能通过重复段落、重复表意、同义反复硬拉字数。
- 如果需要补足篇幅，只能补真正有效的剧情推进、人物动作、关系变化、场景细节或经营信息。
后续升级时，优先补：
- SOP流程更明确
- 正反例更多
- 适用场景更清晰
- 调用顺序更稳定

不要把 skill 改写成：
- 纯理论阐述
- 纯审美感想
- 脱离创作实际的问题清单

### 3. 任何升级都要回到“中文网文写作”场景

### 4. 正文正式交付必须是 Word 文档
后续如果输出小说正文，默认使用真实 Word 文档，优先 `.docx`。
- 小说框架 / 大纲类文件正式交付时，也统一采用真实 Word 文档，优先 `.docx`。
禁止继续使用 HTML 伪装 `.doc` 作为正式成稿交付。
- 章节字数统一执行：每章目标 3200—3800 字，任何一章最低不低于 3200 字。
- Word 版式统一参照中文常用公文 / 公务文档习惯：标题黑体三号居中，正文宋体小四，首行缩进 2 字符，固定 29 磅行距（可接受 28—30 磅），段前段后 0 磅，页边距上 2.54 厘米下 2.54 厘米左 2.8 厘米右 2.6 厘米。

### 3. 任何升级都要回到“中文网文写作”场景
这套资料的服务对象不是泛写作，而是：
- 中文小说
- 中文网文
- 长篇连载
- 开篇、连载、修稿、统一文风、人物稳定性维护

如果后续扩展，也要优先保证这条主线不丢。

## 五、后续升级时必须遵守的规则

### 1. 升级 skill 前，先保留原有 SOP 段
每个 skill 当前都应该包含：
- 核心目标
- 基本原则
- SOP流程
- 正反例
- 修订流程
- 输出要求

后续升级时，只能增补或微调，不要把 SOP 段删掉。

### 2. 如果新增内容，优先加在这几个位置
- “适用场景 / 不适用场景”
- “进阶正反例”
- “与其他 skill 的调用关系”
- “典型错误案例”

### 3. 如果发现某个 skill 开始和别的 skill 重叠
优先做的是：
- 划清边界
- 在总控 skill 和索引清单里补说明

不要简单合并，除非整个体系重构。
