# 下一本小说直用工作流

这份文件只做一件事：

- 把这套模板变成下一本小说可以直接复制开工的执行流程

默认分五个阶段走，不要一上来就把所有资料都喂给模型。

## 一、输入阶段

开书不是先手填八份规划文件。

默认先做一件事：

1. 把你的原始输入写进 `开书输入.md`

这里的原始输入可以是：

- 一个粗脑洞
- 一版现成大纲
- 人物关系草稿
- 平台风格要求
- 你已经写好的设定碎片

这一步只要求“把你已有的东西交出来”，不要求你先把结构整理好。

## 二、初始化阶段

让 Codex 先把原始输入归一化成开书资料，而不是你手工分发到各个文件里。

默认读取：

1. `开书输入.md`
2. `项目规则.md`
3. `当前有效规则卡.md`
4. `SOP资料/workflows/开书初始化工作流.md`
5. `小说框架/09_当前卷执行状态卡_模板.md`
6. `小说框架/10_当前章任务卡_模板.md`

默认产出：

1. `小说框架/00_作品定位.md`
2. `小说框架/01_世界观与主线.md`
3. `小说框架/02_人物关系表.md`
4. `小说框架/06_卷划分.md`
5. `小说框架/03_总目录.md`
6. `小说框架/04_节奏设计.md`
7. `小说框架/05_作品简介.md`
8. `小说框架/07_人物小传.md`
9. 第一卷执行状态卡
10. 第 1 章任务卡

如果原始输入缺少关键项，Codex 只补问最少必要信息，不开长问卷。

最少只补这些：

- 主角是谁
- 主角当前最想解决什么
- 最大冲突是什么
- 故事准备往哪走
- 你想要什么平台感或风格感

## 三、从初始化切到连载

初始化完成后，先检查规划层和活跃卡，不再继续反复投喂原始输入。

检查目标不是继续扩写，而是确认这几件事：

- 书写什么
- 谁推动故事
- 每卷各自解决什么
- 整体推进怎么走

切换到连载前，再确认一次：

- `当前有效规则卡.md`
- `项目规则.md`
- `SOP资料/说明文档/Claude-Mem与RTK接入规则.md`
- `SOP资料/workflows/低Token连载工作流模板.md`

从这一步开始，`开书输入.md` 退回“输入源”，不再进入每章默认上下文。

## 四、单章最小执行循环

每一章都按这个顺序走：

1. 先看 `当前有效规则卡.md`
2. 再看当前卷执行状态卡
3. 再看当前章任务卡
4. 只回读前 1 章正文；承接复杂时最多回读前 2 章
5. 起草或修正文
6. 逐句通读一次，单独清错字、病句、语感跑偏
7. 跑章节验收
8. 更新 4 处文件：
   - 当前卷执行状态卡
   - 当前章任务卡
   - `进度记录.md`
   - `章节验收记录.md`

只有在下面这些情况，才回看更多材料：

- 当前章和前文状态明显对不上
- 自动验收疑似误报
- 某条旧线索必须回查落点
- 要改卷节奏或改总目录

## 五、低 Token 的真正做法

不要把“开书输入 + 总目录 + 进度记录 + 验收记录 + 多章正文”当日常上下文。

日常只保留四类上下文：

1. `当前有效规则卡.md`
2. 当前卷执行状态卡
3. 当前章任务卡
4. 前 1 到 2 章正文

再用这条命令生成一份最小上下文包：

```bash
python3 scripts/prepare_chapter_context.py \
  --volume-card 小说框架/第一卷执行状态卡.md \
  --task-card 小说框架/当前章任务卡.md \
  --output 小说框架/当前章上下文包.md
```

以后默认只把：

- `当前章上下文包.md`
- 当前待写章节源稿 / 待修章节正文

交给模型。

原始大纲和脑洞的正确位置是：

- 开书初始化时读取一次
- 大改规划层时按需回读

不是：

- 每章重复投喂
- 和状态卡、任务卡一起长期陪跑

## 六、Claude-Mem 与 RTK 怎么接

这两个工具只接在“辅助层”，不接在“正文事实层”。

### Claude-Mem

只允许它记：

- 固定工作流
- 反复出现的修订模式
- 工具命令和排障经验
- 跨会话仍然稳定的偏好

不允许它替代：

- 当前卷执行状态卡
- 当前章任务卡
- 人物关系、资源状态、时间线事实
- 下一章执行口

换句话说：

- Claude-Mem 记“怎么工作”
- 项目文件记“故事现在是什么”

### RTK

RTK 只用来压终端输出，不用来压小说语料。

推荐场景：

- `rtk tree`
- `rtk find`
- `rtk grep`
- `rtk git status`
- `rtk git diff`
- `rtk log`

不要用于：

- 正文源稿
- 当前卷执行状态卡
- 当前章任务卡
- 验收记录全文

这些文件一旦被压缩，细节会丢，反而更容易写乱。

## 七、总目录什么时候才回读

`小说框架/03_总目录.md` 不再是每章默认上下文。

只在三种时候回读：

1. 新建下一章任务卡
2. 卷节奏要重排
3. 验收发现本章可能没按卷目标推进

总目录的职责是“规划”，不是“每章陪跑”。

## 八、状态卡怎么防膨胀

状态卡不是“每章再补一条摘要”。

必须这样维护：

- 每个栏目最多 4 条
- 超过就合并成“当前稳定状态”
- 已经失效的事实立刻删掉
- 推断单列，不伪装成事实
- 下一章执行口只保留当前这一章真的要接的内容

如果状态卡越写越长，token 一定会重新失控。

## 九、卷结束时怎么收口

一卷收口时，只做这几件事：

1. 把 `进度记录.md` 和 `章节验收记录.md` 的旧详单转入 `归档/`
2. 新建下一卷状态卡
3. 重写当前章任务卡，让它只服务下一章
4. 不把上一卷的整卷复述继续带进下一卷上下文

## 十、默认入口文件

开书初始化时默认入口顺序固定为：

1. `README.md`
2. `开书输入.md`
3. `SOP资料/workflows/开书初始化工作流.md`
4. `SOP资料/说明文档/Codex开书初始化提示模板.md`
5. `当前有效规则卡.md`

进入单章连载后，默认入口顺序固定为：

1. `README.md`
2. `当前有效规则卡.md`
3. 当前卷执行状态卡
4. 当前章任务卡
5. `SOP资料/workflows/低Token连载工作流模板.md`

如果不知道这章该从哪个 skill 进，再去看：

- `SOP资料/workflows/技能索引清单.md`
- `SOP资料/skills/小说写作总控skill/SKILL.md`
